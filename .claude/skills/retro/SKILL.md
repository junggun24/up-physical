# 회고 (Improvement Loop의 심장박동)

## 절차

1. **수집** — 회고 구간의 증거를 모은다:
   - `git log --oneline --since=<구간>` + 주요 PR
   - `.harness/solutions/` `plans/` 신규 항목, Notion 환류 로그
   - 실패했던 것: 반려된 계획, 재발한 버그, 게이트 우회 시도
2. **지표 점검** (methodology.md의 성공지표):
   - 환류율: 작업 대비 wiki/skill/fixture/solution 갱신 수 — 0에 수렴하면 경보
   - 첫-패스 완료율: 사람 개입 없이 완료조건까지 간 비율
   - 50/50 점검: 시스템 개선에 실제로 시간을 썼나
3. **3질문**:
   - 이번 구간 **가장 반복된 마찰**은? → 스킬/러너로 자동화 후보
   - **같은 문제를 두 번** 푼 적 있나? → solutions 누락, 즉시 기록
   - 하네스 문서 중 **틀린 채 방치된 것**은? → Trust Rule로 즉시 수정
4. **산출** — 개선 항목을 티켓화(plan-ticket)하고, 회고 요약을 Notion 환류 로그에 1항목 추가.

## 규칙

- 회고 산출물 없는 회고 금지 — 최소 1개 개선 티켓 또는 "개선 불필요 근거".
- 사람 비난 없음, 시스템만 고친다 (마찰의 원인은 하네스의 구멍).
