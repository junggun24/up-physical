# 엔지니어링 리뷰 — 설계 잠금

대상: 계획 문서(`.harness/plans/*.md`) 또는 설계 제안. 목적: **구현 시작 전 마지막 기술 관문**.

## 검토 항목

1. **경계 정합** — 우리 상시 정책과 충돌하나?
   (Contract-first / 엔진 로직은 Python 뒤 / 부작용 순서 / 멱등성 / 큐는 Postgres)
2. **대안 검증** — 거절한 대안이 기록돼 있고, 거절 이유가 사실에 근거하나?
   대안이 1개뿐이면 반려 (탐색 부족).
3. **가장 불확실한 것 먼저** — 단계 순서가 리스크 역순인가? 검증 싼 것부터가 아니라
   모르는 것부터인가?
4. **되돌릴 수 있나** — 마이그레이션·계약 변경은 롤백 경로가 있나? 없으면 명시됐나?
5. **완료조건 실행 가능성** — 각 체크포인트가 실제로 실패할 수 있는 검증인가?
6. **복잡도 예산** — 새 의존성·새 인프라가 정말 필요한가? 기존 자산(solutions/ 포함)으로 안 되나?

## 판정 (반드시 하나)

- **LOCK** — 구현 시작 가능. 계획 문서에 `승인(기술): eng-review LOCK <날짜>` 기록.
- **CONDITIONAL** — 명시 조건 반영 후 재검토 없이 진행 가능. 조건을 계획에 추가.
- **REJECT** — 사유와 함께 반려. 재설계 후 재검토.

## 규칙

- 취향 반려 금지 — 반려 사유는 정책 위반·사실 오류·리스크 순서 문제만.
- 판정 근거에 코드 확인이 필요하면 추측 말고 읽는다 (`파일:라인` 인용).
