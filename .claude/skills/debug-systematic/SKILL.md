# 체계적 디버깅 (추측 금지)

"아마 이거겠지"로 코드를 고치지 않는다. 증거 없는 수정은 두 번째 버그다.

## 1. 재현 고정

- 실패를 **결정적으로 재현**하는 최소 입력을 만든다 → 가능하면 `.harness/fixtures/` 샘플로.
- 재현 안 되면 디버깅이 아니라 관찰 단계다: 로그·조건을 좁혀 재현부터.

## 2. 가설 · 이분 탐색

- 관찰(출력·로그 원문)에서 가설을 세운다. 가설은 **반증 가능한 형태**로.
- 탐색 공간을 절반씩 줄인다: 계층(경계→저장→큐→엔진), 시간(어느 커밋부터 — `git bisect`), 데이터(어느 필드부터).
- 한 번에 하나만 바꿔 확인한다.

## 3. 근본 원인 확정 (증거)

- "이 줄이 이 입력에서 이렇게 동작해서" 수준까지 내려간다.
- 증거: 해당 지점의 실제 값 출력, 최소 재현 테스트가 그 지점을 통과/실패하는 것.
- 증상 은폐(재시도 추가, nil 체크만 추가 등)로 끝내지 않는다 — 원인이 설명 안 되면 아직이다.

## 4. 수정 → 회귀 고정 → 환류

1. 원인을 고치고, 재현 케이스를 **회귀 테스트/fixture로 고정** (TDD: 실패 확인 → 수정 → 통과 확인).
2. `check.sh` 전체 통과.
3. `.harness/solutions/` 에 기록 (증상 원문 포함 — 다음에 grep으로 발견되도록).
