# 보안 검토

## 절차

1. **기준 로드** — `.harness/wiki/security.md` (위협 모델·규칙·알려진 백로그).
2. **변경 스코프 판별** — diff에서 다음을 건드리는지 확인:
   `internal/auth`, 핸들러의 인증/스코프 로직, `contract` 경계, env/비밀, 외부로 나가는 부작용.
3. **체크리스트 실행** (해당 영역만):
   - 인증/인가: 토큰 검증 우회 경로? 사용자 간 리소스 격리 유지? `ALLOW_DEV_AUTH` 영향?
   - 입력 경계: 새 입력이 검증 없이 내부로 흐르나? 크기 제한? 파라미터화 쿼리 유지?
   - 비밀: 코드·로그·커밋·에러 응답에 비밀/내부정보 노출?
   - egress: 새 외부 호출이 stage 인터셉트 대상에 등록됐나? fail-closed 유지?
4. **탐색 방법** — 추측하지 말고 코드로 확인: 핸들러부터 스토어까지 데이터 흐름을 따라간다.
   `grep -rn "os.Getenv\|Error()\|X-User-Id"` 같은 스캔으로 노출 지점 전수 확인.
5. **보고** — 발견별로: 심각도(차단/높음/중간/낮음) + `파일:라인` + 재현/영향 + 수정 제안.
6. **환류** — 새 위협·결정을 `.harness/wiki/security.md` 결정 로그에 추가.
   반복될 점검 패턴은 이 스킬에 체크 항목으로 추가한다.

## 완료 판정

- 차단/높음 발견이 0이거나, 각각에 수정 커밋+재검증 증거가 있다.
