# 시안 샷건 — 발산 → 평가 → 수렴

대상: 화면/컴포넌트 1개 (예: 결과 화면, 오버레이 비교, 촬영 가이드).

## 1. 발산 (3~4안 — 서로 정말 달라야 함)

각 안은 **접근 축이 달라야** 한다 (색만 다른 변형 금지):
- 정보 우선순위가 다른 안 (점수 중심 vs 교정 중심 vs 비교 중심)
- 인터랙션이 다른 안 (스크롤 vs 탭 vs 오버레이)
- 밀도가 다른 안 (한 화면 압축 vs 단계 분리)

각 안: 레이아웃 스케치(HTML 목업 또는 Figma) + 핵심 의도 한 줄.
Figma 작업 시 Figma MCP 사용 (`/figma-use` 선로드).

## 2. 평가 (채점표 — 디자인 원칙 기준)

| 기준 (wiki/design.md) | 가중치 |
| --- | --- |
| "하나만 고친다" 집중도 | ×3 |
| 상태 완전성 (대기/실패/빈 포함 설계 용이성) | ×2 |
| 야외 사용성 (대비·한 손·타깃 크기) | ×2 |
| 계약 정합 (표시 데이터가 분석 결과에 존재) | 통과/탈락 |
| 구현 비용 | ×1 |

각 안 0~10 채점 + 강점/약점 한 줄.

## 3. 수렴 · 기록

- 승자 정교화. 탈락안의 좋은 요소는 이식 가능.
- **거절한 시안과 이유**를 `wiki/design.md` 결정 로그에 기록 (날짜 포함).
- 산출물: 승자 시안 + 상태별 정의 + 핸드오프 명세 (design-review 로 검증).
