# 하네스 환류 (self-review)

작업을 닫기 전 5분. 아래 질문에 답하고 해당 위치를 갱신한다.

## 질문 → 갱신 위치

| 질문 | 예 → 갱신 |
| --- | --- |
| 코드와 문서가 어긋난 걸 발견했나? | `.harness/wiki/` 해당 문서 (코드가 진실) |
| "왜 이렇게 했지"를 나중에 물을 결정이 있었나? | wiki 해당 문서의 결정 로그 (Intent, 날짜 포함) |
| 다음에 또 할 절차를 새로 알아냈나? | `.claude/skills/<이름>/SKILL.md` 신설 또는 기존 스킬 보강 |
| 새 버그/엣지케이스를 찾았나? | `.harness/fixtures/` 재현 샘플 + 회귀 테스트 |
| 승인할 만한 기준 출력이 나왔나? | `.harness/golden/` (사람 승인 후) |
| 상시 정책이 바뀌었나? | 루트 `AGENTS.md` (짧게 유지 — 정말 상시인 것만) |

## 규칙

- **갱신 0건이면 그 이유를 한 줄로 남긴다** ("배움 없음 — 단순 오타 수정" 등).
  환류 여부 자체가 성공지표(환류율)다.
- 지식은 태깅한다: **Fact**(현재 동작) / **Intent**(이유) / **Procedure**(방법).
- wiki는 검색 가능하게 짧은 문서 여러 개로 분할 유지. 한 문서가 100줄 넘으면 분할 검토.

## 완료 판정

- 갱신 커밋이 작업 커밋과 함께 있다 (또는 "배움 없음" 사유가 보고에 있다).
