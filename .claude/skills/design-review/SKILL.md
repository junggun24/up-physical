# 디자인 리뷰 — 원칙 채점 + 인계 판정

대상: 시안, 화면 플로우, 핸드오프 문서, (앱 생기면) 실제 빌드 화면.

## 1. 원칙 채점 (0~10, 근거 필수 — wiki/design.md 기준)

1. **하나만 고친다** — 교정 포인트가 1개로 압축돼 있고 시각 위계가 그걸 말하나?
2. **상태 완전성** — 성공/실패/대기/빈 상태가 전부 정의됐나? 비동기(202→폴링) 대기 UX가 있나?
3. **야외 사용성** — 밝은 햇빛 대비, 한 손 조작 리치, 터치 타깃 크기.
4. **계약 정합** — 화면의 모든 데이터가 분석 결과 계약에 실존하나?
   (없는 데이터 요구 = 즉시 탈락, 계약 변경 합의로 회부)
5. **일관성** — 기존 화면들과 컴포넌트·패턴 재사용.

## 2. 인계 판정 (반드시 하나)

- **HANDOFF** — 개발이 추가 질문 없이 구현 가능. 부족한 질문이 0개.
- **REVISE** — 구체 수정 목록과 함께 반려 (항목별 P1/P2/P3).
- 판정 테스트: "구현자가 물어볼 질문 3개를 지금 만들어보라" — 만들어지면 REVISE.

## 3. 기록

채점표와 판정을 티켓에 첨부. 반복되는 감점 패턴은 `wiki/design.md` 원칙에 추가 (환류).
