# 코드 리뷰 — 버그 사냥 + 수정

대상: 인자로 받은 것 (없으면 `git diff HEAD` + 스테이징, 그것도 없으면 마지막 커밋).

## 1. 렌즈별 정밀 검토 (스타일 아님 — 결함만)

| 렌즈 | 이 코드베이스에서 특히 볼 것 |
| --- | --- |
| 정확성 | 경계값, nil/빈 슬라이스, 에러 무시(`_ =`), 조기 return 누락 |
| 계약 | `contract.Validate` 우회 경로, INV-1..8과 코드 불일치, fixture 미갱신 |
| 순서·원자성 | "스토리지 성공 후 DB 커밋" 위반, 트랜잭션 경계, 부분 실패 시 상태 |
| 동시성 | 워커 다중 인스턴스 가정(SKIP LOCKED), 공유 상태, 파이프 재시작 경합 |
| 멱등성 | 같은 키/재시도 시 중복 부작용, at-least-once 소비의 이중 처리 |
| 에러 노출 | `err.Error()`가 응답으로 나가는 경로 (알려진 P2 계열) |

## 2. 판정·수정

- 발견은 **P1(차단)/P2(권장)/P3(선택)** + `파일:라인` + 실패 시나리오(입력→잘못된 결과).
- **P1은 지금 고친다**: TDD로 실패 재현 테스트 먼저 → 수정 → `check.sh` 재검증.
- P2/P3는 티켓화(제목·근거)하고 막지 않는다.

## 3. 보고 형식

```
대상: <diff 범위>
P1: n건 (각각: 위치 · 시나리오 · 수정 커밋 · 재검증 증거)
P2/P3: 목록 + 티켓 링크
통과 근거: check.sh 출력 요약
```

## 규칙

- 발견 0건이면 "0건인 이유"를 렌즈별로 한 줄씩 — 안 본 것과 없는 것을 구분한다.
- 수정 후 배움이 있으면 `harness-feedback` (solutions/fixture 축적).
