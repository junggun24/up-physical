# CEO 리뷰 — 전략 범위 도전

대상: 인자로 받은 것 (기획서 / 티켓 / 계획 문서 / 기능 아이디어 / "현재 로드맵").
인자가 없으면 [MVP 기획서](https://app.notion.com/p/3acb61e8ae4280b3b28de69638337efc)와 작업 보드 전체를 대상으로 한다.

## 1. 강제 질문 6문 (office-hours — 하나라도 답이 막히면 빨간불)

1. **누구의 어떤 문제**를 푸는가? (페르소나 없이 "사용자들" 금지)
2. **왜 지금**인가? 6개월 뒤에 하면 뭐가 달라지나?
3. **이게 없으면** 사용자는 뭘 하나? 그 대안 대비 10배 나은가?
4. **성공을 어떻게 측정**하나? 숫자와 기한이 있나?
5. **가장 큰 리스크**는? 그걸 가장 싸게 검증하는 방법은?
6. **죽여야 할 것**은? 지금 리스트에서 뺄 하나를 고른다면?

## 2. 범위 도전 4모드 (plan-ceo-review — 대상에 맞는 모드만)

| 모드 | 도전 |
| --- | --- |
| **절반** | 범위를 절반으로 줄여도 같은 가설을 검증할 수 있나? 어느 절반을 버리나? |
| **제로** | 아예 안 만들고 검증할 방법은? (수동 운영, 목업, 오즈의 마법사) |
| **순서** | 지금 순서가 최선인가? 가장 불확실한 걸 가장 먼저 검증하고 있나? |
| **완료조건** | 완료조건이 "노력"이 아니라 "결과"를 재나? 게이트가 실제로 실패할 수 있는 기준인가? |

## 3. 산출물 (반드시 이 형식)

```
대상: <무엇을 리뷰했나>
빨간불: <막힌 질문들 — 없으면 "없음">
권고: 항목별 [유지 | 축소(어떻게) | 제거 | 보류(조건)] + 한 줄 근거
반영: 기획서/보드에 반영할 구체 변경 (반영 여부는 사람이 결정)
```

## 규칙

- 좋은 말 금지 — 이 스킬의 가치는 반대 심문이다. 칭찬은 다른 데서 한다.
- 권고는 실행 가능해야 한다 ("고민 필요" 금지, "F6을 베타 이후로 보류" 수준).
- 결정은 사람 몫: 권고를 기획서에 자동 반영하지 않는다 (명시적 승인 후 반영).
- 반영이 결정되면 `plan-ticket`/기획서 갱신 + 환류 로그 기록으로 이어간다.
