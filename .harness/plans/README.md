# plans — 구현 계획 문서

작지 않은 작업(반나절 이상, 또는 계약·스키마·보안 영향)은 구현 전에 계획을 여기 남긴다.
작성 절차: `write-plan` 스킬. 파일명: `YYYY-MM-DD-<slug>.md`.

## 왜

- 계획이 코드보다 중요하다 (검토 80% 원칙). 계획 단계의 오류가 가장 싸게 잡힌다.
- 계획 문서는 비동기 검토·인수인계·재현의 단위다. 승인은 명시적으로 (침묵 ≠ 동의).

## 형식

```markdown
# <제목>
승인: <미승인 | 승인자/날짜>

## 목표 / 완료조건   ← plan-ticket의 4요소 상속
## 조사              ← 코드베이스 유사 패턴, wiki, 외부 자료
## 설계              ← 접근·트레이드오프·거절한 대안과 이유
## 단계              ← 체크포인트 단위 (각각 검증 가능)
## 리스크            ← 가장 확신 없는 부분
```

완료된 계획은 지우지 않는다 — 결과와 어긋난 부분을 기록하고 solutions/wiki로 환류.
