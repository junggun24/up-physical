## 증상

`feat(infra): 로컬 스택 재구축으로 P2 마감 (...)` (51자) 커밋이 형식 위반으로 거부.
같은 구조의 영어 제목은 통과 → 길이 판정 의심.

## 근본 원인

git 훅 프로세스는 LC_ALL 미설정(C 로케일)으로 실행된다. C 로케일에서 grep의 `.`은
바이트 단위 매칭이라 UTF-8 한글(3바이트/자)이 3배로 계산돼 `.{0,71}` 상한을 초과.

## 해결

`.githooks/commit-msg` 수정:
1. 사용 가능한 UTF-8 로케일(en_US.UTF-8 → C.UTF-8 → ko_KR.UTF-8 순)을 찾아 LC_ALL 설정
2. 길이 검사를 정규식에서 분리해 `wc -m`(문자 수)으로 명시적 판정 — 초과 시 현재 자수 표시

## 재발 방지

- 훅 거부/통과 테스트에 한글 제목 케이스 포함 (51자 통과 · 73자 거부 확인).
- 교훈: 셸 도구의 문자 처리엔 로케일이 숨은 입력이다 — 훅·CI 스크립트는 로케일을 명시한다.
