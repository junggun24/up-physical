# security — 보안 기준 · 위협 모델 · 결정 로그

> 태그: **Fact/Intent**. up-security 에이전트의 검토 기준. 새 위협·결정은 여기 환류.

## 데이터 특수성 (위협 모델의 출발점)

- 입력 = **신체 움직임 데이터**(골격 스트림). 원본 영상은 온디바이스에 남고 서버로는
  키포인트 시계열만 온다 — 이 경계 자체가 프라이버시 설계다. 유지할 것.
- 스트림 원본 바이트가 objstore(`sessions/{id}/stream.json`)에 보존된다.
  → 버킷 접근 제어가 최전선. 보존 기한·삭제 경로는 미정(백로그).

## 현재 상태 (Fact — 코드 기준)

| 영역 | 상태 |
| --- | --- |
| 인증 | 자체 signup/login + JWT(HS256, TTL 30일). `internal/auth` |
| dev 우회 | `ALLOW_DEV_AUTH=true` 시 `X-User-Id` 무검증 신뢰 — **prod 금지** |
| 입력 경계 | `contract.Parse+Validate`(INV-1..8) + 본문 16MB 제한 + 멱등키 필수 |
| DB | pgx 파라미터화 쿼리 (SQL 인젝션 방어) |
| 에러 노출 | ⚠ 일부 problem+json에 `err.Error()` 원문 노출 — 내부정보 유출 소지 (백로그) |
| 비밀 | env로 주입(`JWT_SECRET`, S3 키). `.env`는 gitignore |

## 규칙

1. **fail-closed** — 테스트 모드/환경이 불확실하면 write 거부. 부작용 egress(메일·결제·webhook)는
   stage에서 전부 인터셉트.
2. **prod 검증은 read-only** — smoke는 GET/로그인만, write 금지.
3. **사용자 격리** — 모든 조회는 인증 주체의 리소스로 스코프. 교차 접근은 차단급 버그.
4. **비밀은 코드·로그·커밋에 절대 없다.** 유출 시 즉시 로테이션.
5. 보안 영향 변경(auth·경계·egress·비밀)은 up-security 리뷰를 머지 게이트로.

## 알려진 백로그 (우선순위순)

1. 에러 응답에서 내부 오류 문자열 제거(로그에만 남기고 응답은 일반화).
2. JWT 검증의 게이트웨이/관리형 IdP 이관(UP-12) 및 토큰 TTL 재검토(30일은 길다).
3. 골격 데이터 보존 기한·사용자 삭제 요청 경로 설계.
4. 잡/세션 조회 엔드포인트의 소유자 검증 전수 확인.
