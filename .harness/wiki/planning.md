# planning — 제품 방향 · 로드맵 · 티켓 규칙

> 태그: **Intent/Fact**. 원본: Notion [업 피지컬](https://app.notion.com/p/2e0b61e8ae4280af9f3fc6caa71c2417) + 작업 보드.

## 제품 한 줄

**촬영 → 코치 비교 → 한 가지 교정 → 성장** 코칭 루프를 빠르게 실사용자에게 검증한다 (MVP).

## 현재 가정 (2026-06 기준)

- **Android(갤럭시) 우선 출시 · 포핸드 MVP.** iOS는 이후 단계.
- 엔진(P1)은 포핸드 기준 검증 완료 → 병목은 **백엔드 이식(Go)과 앱 통합**.

## 핵심 경로 (Critical Path)

```
P0 계약·스키마 → P2 백엔드(인제스션·워커·DB·스토리지) → P3 Android 앱 → P4 배포·심사·출시
```

## 차별화 4종 (경쟁력 — 스코프 판단 기준)

| 기능 | 역할 |
| --- | --- |
| 피드백 우선순위화 — "이번에 고칠 단 하나" | 핵심 가치 |
| 코치 나란히 비교(오버레이) | 히어로 기능 |
| 성장 추적 그래프 | 리텐션·전환 엔진 |
| 실시간 촬영 가이드 | 활성화율(좋은 클립 확보) |

## 티켓 템플릿 (필수)

```
목표(What) / Why / 제약 / 완료조건(검증 가능: Invariant·Golden·측정치)
```

완료조건 없는 티켓 금지. How 지시 최소화. 우선순위는 "MVP 핵심 루프 검증 기여도"로 판단.

## 주요 백로그 (Notion 작업 보드 발췌)

온디바이스 BlazePose 통합, 분석 워커 서비스화, DB 스키마(N명), 코치 오버레이 화면,
성장 추적 그래프, 처리시간 실측→UX 예산, 클로즈드 베타(가치 검증), 분석 엔진 오프라인 검증.
