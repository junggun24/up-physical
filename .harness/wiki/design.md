# design — 디자인 원칙 · 핵심 화면 · 핸드오프 규칙

> 태그: **Intent**. 디자인 결정과 이유를 여기 축적한다 (환류 대상).

## 원칙

1. **하나만 고친다** — 결과 화면은 교정 포인트를 우선순위 1개로 압축. 목록 나열 금지.
2. **비동기가 기본** — 업로드→202→폴링 구조. 대기/분석중/실패/빈 상태를 모든 화면에 정의.
3. **야외 사용** — 코트(밝은 햇빛, 한 손, 땀) 환경. 대비·터치 타깃 크게.
4. **계약 정합** — 화면이 표시하는 데이터는 분석 결과 계약(점수·구간·타점·교정)에 존재해야
   한다. 디자인이 계약에 없는 데이터를 요구하면 기획·개발과 계약 변경을 먼저 합의.

## 핸드오프 규칙 (디자인 → 개발)

- 산출물: 화면 플로우 + 상태별 정의(성공/실패/대기/빈) + 컴포넌트 명세 + 카피.
- 완료조건: 개발이 **추가 질문 없이** 구현 가능한가.
- Figma 작업은 Figma MCP로. 파일/프레임 링크를 티켓에 첨부.
